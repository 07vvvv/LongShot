# LongShot

Windows 滚动长截图工具。按热键框选一块区域，用滚轮把内容滚过去，单击左键结束，得到一张完整长图。

单个约 49MB 的 exe，自包含 .NET 运行时，**目标机器不需要装任何东西**。

## 用法

```
按热键  →  拖拽框选区域  →  滚轮上下滚动  →  单击鼠标左键结束
```

结束时长图会：

- 保存到磁盘（见下方「输出位置」）
- 复制进剪贴板
- 自动用系统看图器打开

首次运行会自动启用 `Ctrl+Alt+L` 作为热键，随时可以在设置界面里改。

## 特性

- **自定义全局热键**：任意 `Ctrl / Alt / Shift / Win` 组合。设置时会**试注册**检测冲突（Windows 上唯一可靠的判定方式），被占用就明确告诉你"无法设置"，含 `Win` 的组合还会要求试按确认——因为存在"注册成功却收不到"的情况。
- **双向滚动**：向下、向上都能截；往回滚到已经截过的范围不会重复追加内容。
- **DPI 感知**（PerMonitorV2）：框选范围和实际截到的范围严格一致，125% / 150% 缩放下不会错位。
- **抓取时不干扰操作**：选区确定后遮罩彻底透明且鼠标穿透，你像平时一样点击和滚动真正的应用；左键由低级鼠标钩子单独拦下用来结束。
- **异常兜底**：任何未处理异常都不会再弹出"未经处理的异常"崩溃框，而是记录到日志并给一句人话提示。

## 输出位置

长图按优先级挑选**确实可写**的目录：

1. `图片\LongShot\`
2. `LongShot.exe` 同级的 `captures\`
3. 系统临时目录

文件名形如 `longshot_20261015_231045_123.png`（精确到毫秒，连拍不会互相覆盖）。

想看当前机器上哪个目录可用：

```powershell
LongShot.exe --pathtest
```

## 快捷键配置位置

- `%APPDATA%\LongShot\hotkey.json`
- 写不进去时回退到 exe 旁边，**两处都失败会在界面上明确告知**（不会再出现"设置好了、重启就没了"却毫无提示的情况）

## 自检

程序内置了一整套可复跑的自检，都不需要人盯着：

| 命令 | 检查内容 |
|---|---|
| `--stitchtest` | 配准算法（双向偏移、步长突变、无滚动、累积模型、性能） |
| `--aligntest` | 框选坐标与抓帧坐标是否一致（放一个纯色标记窗口实地抓） |
| `--overlaytest` | 选区窗口的鼠标命中、穿透、抓帧是否被自己污染、钩子行为 |
| `--grabtest` | 屏幕抓取在本机是否真能拿到画面 |
| `--uitest` | 设置界面构造、热键管理器、清除快捷键 |
| `--pathtest` | 长图输出目录的可写性 |
| `--logprobe` | 启动日志落点的探测结果与失败原因 |
| `--startuptest` | 启动耗时 |
| `--probe` | 探测一批常见组合键在本机是否被占用 |
| `--makeicon` | 重新生成 `app.ico` |
| `--uishot` | 抓设置界面和浮层的截图 |

自检输出会镜像到 `%LOCALAPPDATA%\LongShot\diag.log`（GUI 子系统下 stdout 不建立）。

## 启动日志

位置固定在 `%LOCALAPPDATA%\LongShot\LongShot-startup.log`（形如 `C:\Users\<你>\AppData\Local\LongShot\LongShot-startup.log`），与热键配置同一个套路——**不往 exe 所在目录写任何东西**，免得 exe 放在桌面或下载目录时在你眼皮底下留杂物。每次启动追加十来行，是「打不开 / 卡住」时最直接的证据：

- 进程创建到各阶段花了多久（`进程创建至今`）
- **这次是怎么被启动的**：exe 路径、基础目录、当前工作目录、命令行参数、`STARTUPINFO` 里的显示方式
- 单实例判定（唤出已有窗口 / 照常启动）
- 配置加载与热键注册结果
- 窗口最终有没有显示出来

落点是**按优先级探测**的，第一个确实可写的胜出：`%LOCALAPPDATA%\LongShot\` → `%APPDATA%\LongShot\`（与热键配置同目录）→ exe 旁边 → `%TEMP%`。正常机器停在第 1 个；前两个都被企业策略锁死的极端情况才会退到 exe 旁边——总好过「打不开且查无实据」。

想知道这台机器上最终选了哪个、每个候选为什么失败：

```powershell
LongShot.exe --logprobe
```

结果写在 exe 旁边的 `_logprobe.txt` 里。

### 「从快捷方式打不开、进文件夹双击却正常」怎么查

先看日志里的 `启动环境` 那一行，两种启动方式的差别直接摆在那里：

| 日志线索 | 含义 |
|---|---|
| `显示方式=SW_SHOWMINNOACTIVE（最小化…）` | 快捷方式设了「运行方式：最小化」。程序会把窗口恢复正常并补记一行 `窗口启动时处于最小化…已恢复正常大小` |
| `当前目录=` 不是 exe 所在目录 | 正常。所有资源都按 exe 路径解析，不依赖工作目录 |
| `参数=[…]` 里有东西 | 快捷方式带了参数；若带的是 `--probe` 这类自检参数，程序跑完就退，**不显示窗口** |
| 连 `=== 启动` 都没有 | 程序压根没跑起来（不是界面问题）：快捷方式目标路径失效、被 SmartScreen 拦、或单文件版解压时临时目录被安全软件锁住。换个目录（如 `D:\LongShot`）再试 |

**临时目录写不进去以前会直接打死程序**：`Application.EnableVisualStyles` 要往 `%TEMP%` 写一个临时清单文件，临时目录被杀软锁住、被组策略限制或 ACL 异常时，它抛出的 `UnauthorizedAccessException` 会让程序 100% 起不来——而且崩在异常处理器注册之前，连一行日志都没有。现在这种情况只记一行日志、界面回退成经典外观，功能照旧。

## 从源码构建

需要 .NET 8 或更高版本的 SDK（Windows）。

```powershell
dotnet build -c Release
dotnet run -c Release                        # 直接运行

# 打包成单文件自包含 exe
dotnet publish -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true `
  -p:EnableCompressionInSingleFile=true `
  -p:DebugType=none `
  -o publish
```

## 发布到 GitHub

**双击 `upload-to-github.cmd`** 就行。要指定仓库和标签：

```
upload-to-github.cmd 你的用户名/LongShot v1.0.1
```

它会依次：构建 → 打包 zip → 提交源码 → 推送 → 创建 Release（标签已存在则改为覆盖附件，并保留原有说明）。

> 直接双击 `.ps1` 常会失败：带「来自 Internet」标记的脚本会被默认的 `RemoteSigned` 执行策略拒绝，提示「未对文件进行数字签名」。`.cmd` 包装内含 `-ExecutionPolicy Bypass`，所以双击 `.cmd` 即可。

产物布局：源码进仓库（`bin/obj/publish/zip/启动日志` 都在 `.gitignore` 里），Release 附件是 `LongShot-<Tag>-win-x64.zip`（只含 exe）+ 同名 `.sha256`。

## 已知边界

- **粘性头部 / 固定侧栏**会在长图里重复出现——需要额外的固定区检测，暂未实现。
- **动画或视频区域**会导致配准不可信，这些帧会被跳过，长图里可能缺一小段（浮层会显示"跳过 N 帧"，并提示滚慢一点）。
- 长图总像素上限 3000 万（约 120MB 内存），到顶时浮层会提示结束后再截下一段。
- **重复启动偶尔会多开一个窗口**：Windows 只把前台权限交给当前前台进程，唤醒已有窗口的请求被拒时，程序宁可再开一个，也不让用户看到"点了没反应"。此时新实例的热键会被旧实例占着，状态栏会提示"已被其他程序占用"——那是它自己的另一个实例，关掉其中一个即可。
- exe 未做代码签名，首次运行可能被 SmartScreen 或安全软件拦一下。
